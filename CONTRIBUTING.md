# Contributing

Meaningful changes should arrive through pull requests with a clear intent, scope, tests, and evidence. Architecture changes should use an ADR when the decision is hard to reverse or surprising without context.

Controller changes require regression tests, including negative tests for unauthorized transitions where applicable. New skills may assist workers but must not grant themselves authority. Schema-breaking changes require migration guidance. Failures and rejected attempts must remain traceable; do not rewrite them out of history.

Until the first implementation stage is approved, documentation changes are welcome but control behavior is intentionally not implemented.
